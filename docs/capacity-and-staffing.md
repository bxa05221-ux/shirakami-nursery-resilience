# 定員区分・職員配置設計

## 目的

保育レジリエンスでは、子どもの個別Landscapeだけでなく、**定員・年齢構成・クラス編成・当日出席・職員配置**を同じLandscapeで扱う。

「20人×6クラス＝120人」は本実証システムの運用上限であり、法令上の定員や学級編制を意味しない。

## 1. 定員区分とクラス定員を分離する

### 園レベル

- 施設種別
- 認可・認定等の法的区分
- 施設定員
- 定員区分
- 地域区分
- 年齢別定員・在籍数

### クラスレベル

- 最大6クラス
- 1クラスのシステム上限20人
- 年齢／異年齢構成
- 在籍人数
- 当日出席人数
- 担当職員
- フロート職員
- 個別支援負荷

この二つを混同しない。

## 2. 職員配置は三層で見る

```text
法定・制度上の最低配置
          ↓
園の通常運営上の目標配置
          ↓
個別支援・安全・活動・外部環境による追加配置
```

最低基準を満たしていても、個別支援負荷や活動内容によっては追加配置・活動の分散・環境変更が必要になる。

## 3. 2026年時点の保育所基準をPolicyの例として保持

こども家庭庁の2026年4月資料では、定員20人以上の認可保育所について、配置基準の例として次が示されている。

| 年齢 | 配置基準の例 |
|---|---:|
| 0歳児 | 3:1 |
| 1歳児 | 6:1 |
| 2歳児 | 6:1 |
| 3歳児 | 15:1 |
| 4・5歳児 | 25:1 |

1歳児は5:1配置に対する加算措置があり、3歳児・4歳以上児には経過措置がある。したがって、**システムに固定値として埋め込まず、施設種別・地域・制度年度に応じたPolicyとして管理する**。

> 参考：こども家庭庁「基礎資料」（令和8年4月）

## 4. 120人モデルで見る

6クラス×20人という構成でも、必要職員数を単純に「120÷20」で決めない。

例えば同じ120人でも、

```text
ケースA
4・5歳児中心

ケースB
3歳児中心

ケースC
0〜2歳児が多い

ケースD
個別支援負荷が高い

ケースE
欠勤＋戸外活動＋外部危険情報
```

では、必要な保育体制が異なる。

したがってRuntimeは、**総人数 → 年齢構成 → 個別支援負荷 → 活動 → 外部Landscape → 職員可用性**の順で配置状況を見る。

## 5. 出力

毎日の職員配置画面は、少なくとも以下を表示する。

```text
園定員 / 定員区分
クラス数
クラス別在籍数
クラス別当日出席数
年齢別人数
制度上の最低配置Policy
実配置
フロート職員
個別支援負荷
配置余力
不足・注意
外部Landscape
管理者判断
```

### スレゼンターの出力例

> **今日の配置Landscape**
>
> 3歳児の出席が多く、個別支援負荷も高い状態です。
> 法定Policy上の配置と実配置を確認してください。
> 戸外活動を行う場合、フロート職員を活動側へ移す案と、活動を小集団に分ける案があります。
> 最終判断は管理者・担当職員で行ってください。

## 6. 重要な境界

AIは、

- 配置基準を勝手に変更しない
- 法的適合性を保証しない
- 欠員時の運営可否を決定しない
- 子どもの支援量だけから職員配置を断定しない

一方で、AIは、

- 配置情報を可視化する
- 年齢構成と支援負荷を重ねる
- ヒヤリハットや外部Landscapeとの関係を示す
- 複数の配置案を提示する
- 翌日の保育計画に配置条件を反映する

ことを担当する。

## 7. 第三者評価への接続

```text
定員
 ↓
職員配置
 ↓
保育実践
 ↓
安全・ヒヤリハット
 ↓
子どもの姿
 ↓
Evidence
 ↓
第三者評価
 ↓
改善提案
 ↓
次の配置・保育計画
```

配置そのものだけではなく、**配置と保育の結果の関係**をEvidenceとして蓄積する。
